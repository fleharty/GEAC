## Current state

- **Released:** v0.4.55 — Fusion partners reported in **biological 5′→3′ orientation**. Fusion labels were ordered by internal gene index (`fusion_pair_label` → `(min_index, max_index)`), so the reported `gene_a::gene_b` was arbitrary, not the donor→acceptor direction that defines the functional driver (e.g. EWSR1 5′ in EWSR1::FLI1). Orientation needs gene **strand**, which the index build parsed then discarded: `GeneBody` now keeps `strand`, the index `genes` table gained `strand/tx_start/tx_end`, and a `meta` flag `gene_strand=1` marks strand-bearing indexes (legacy indexes without it fall back to index order — back-compat). `infer_five_prime` (`src/fusions.rs`) votes per spanning read — *aligned gene is 5′ iff (its k-mer block is first in reference-forward SEQ) == (its strand is '+')* — over a majority with a minimum-vote + fraction confidence gate (a real interchromosomal fusion yields a legitimate reciprocal-derivative-junction minority, so the fraction floor is permissive and vote count is the real guard). Parquet/TSV `gene_a/gene_b/chrom_a/chrom_b` and the breakpoints TSV are emitted 5′→3′ when determined; a new **`partner_order`** column records `5to3` vs `index` so a fallback is never mistaken for biology. The internal `pair_key` and per-read `FX`/`FL` tags stay index-ordered (written mid-scan before orientation is known; `FL`'s A/B must stay tied to `FX`). Additive column (`DUCKDB_SCHEMA_VERSION` unchanged); index gains columns + the `gene_strand` flag. Validated on a cell-line dilution series: every gated call matched the known 5′→3′ truth; a capture-limited few-read background correctly abstained. Orientation is independent of index edit distance.
- **Released:** v0.4.54 — Fusion **asymmetric breakpoint-anchor tier** (single-sample, low-input rescue). At low input a real junction is often captured well on one side — many reads converging on a tight breakpoint — but seen by only 1–2 reads on the other, so the symmetric `--min-breakpoint-reads`-on-**both**-sides rule tags it `chimera`. New opt-in `--asym-anchor-reads <N>` keeps such a call PASS when its **dominant** (better-covered) breakpoint has ≥N reads converging within `--asym-anchor-std` bp (default 25), the partner breakpoint has ≥1 read, and the call's `min_mapq` ≥ `--asym-anchor-mapq` (default 20). Requiring the *dominant* side to be tight rejects paralog leakage (whose high-count side is smeared while a minority side coincidentally converges); the MAPQ floor drops multi-mapper leakage reads. Only consulted when `--max-breakpoint-std` is set; **default disabled**. Validated on a cell-line dilution series: recovers additional low-input PASS calls on a hard-to-detect fusion with **zero new false positives** across all samples and controls. `BreakpointStats::asym_anchored`; three inputs exposed in `wdl/experimental/geac_fusions.wdl`. Experimental-only; no schema change. (Also: guard an empty `--exclude-tag` against WDL Array[Nothing] interpolation in the collect WDLs.)
- **Released:** v0.4.53 — Fusion breakpoint consensus: a **strong-support tier** that recovers real fusions the single-threshold filters wrongly rejected, with no loss of specificity. (1) *Chimera*: a real high-depth junction's `bp_*_std` can exceed `--max-breakpoint-std` because splice isoforms and k-mer transition-point noise spread it over tens-to->100 bp; a call with ≥25 converging reads on **both** sides and std ≤250 bp now also PASSes. Low-support artifacts never reach that tier (their support sits at the `--min-breakpoint-reads` floor), so this lifts sensitivity for genuine fusions without admitting them. (2) *Samelocus*: a real translocation whose breakpoint is buried in a repeat is observed only through concordant pairs that co-localize to one chromosome — geometrically indistinguishable from single-locus paralog leakage by distance alone. The discriminator is mechanism: leakage is **spanning-read dominated** at one locus (the same molecule carries both partners' k-mers), whereas the real junction has strong **independent (concordant, non-spanning)** support on both partners. Calls with strong concordant support on both sides are now exempt from `--min-breakpoint-distance`; leakage (spanning-dominated, collapses when spanning reads are subtracted) stays tagged. `compute_breakpoint_stats` gains `strong_support` / `strong_concordant_support`. Experimental-only; no CLI/schema/WDL-input change (the tier thresholds are internal constants).
- **Released:** v0.4.52 — Fusion breakpoint consensus: recommended `--max-breakpoint-std` raised `10 → 100` (a real high-depth junction spreads over tens of bp via splice isoforms + k-mer transition-point noise, while artifacts scatter over 10⁴–10⁷ bp, so `100` separates them with orders-of-magnitude margin), plus a **concordant-pair breakpoint fallback** so the consensus filter no longer rejects real fusions whose junction sits inside an index-excluded repeat. When the breakpoint falls in an intronic repeat (e.g. an Alu) the genome-unique k-mer index has a gap wider than a read, so *no read spans the junction* and the spanning-only logic saw too few reads to pass `--min-breakpoint-reads`. `compute_breakpoint_stats` now supplements spanning reads with concordant single-gene mates, estimating the breakpoint from each read's junction-facing **alignment edge** (gene-A alignment end / gene-B alignment start — the aligner places the read through the repeat, whereas a matched-k-mer offset stops at the index gap and scatters), and reduces all estimates to the dominant cluster (`cluster_around_median`, ±1 kb) before measuring std so deep-body mates can't inflate the spread (also making the std test outlier-robust). Validated on a canonical EWSR1::ERG fusion: converges to `bp_*_std` in the tens of bp on ~85 reads/side and PASSes while remaining the only PASS among 900+ candidates in that sample. Experimental-only; no CLI/schema/WDL change (the cluster window is an internal constant).
- **Released:** v0.4.51 — Mechanism-level fusion false-positive filters (no PoN). Two `geac experimental fusions` flags tag artifacts in the `filter` column without a Panel-of-Normals: `--max-breakpoint-std <BP>` / `--min-breakpoint-reads <N>` tag `filter=chimera` unless both breakpoints are supported by ≥N spanning reads converging within ≤BP bp (catches PCR/ligation chimeras and multi-locus paralogy, whose junctions scatter); `--min-breakpoint-distance <BP>` tags `filter=samelocus` when both breakpoints are same-chromosome within BP bp (catches single-locus leakage from an *unindexed* paralog — e.g. GNA12 reads split between GNA13/GNA11, fabricating a fusion whose tight breakpoint defeats the consensus filter). Validated with no PoN: 1 real PASS vs 533–1252 artifacts tagged on a tumor, 0/1177 calls passing in a normal. Confirmed the residual FPs are chimeric molecules + paralog leakage, **not** k-mer-index leakage (the genome-unique index is sound). Filters are opt-in and *tag* (rows kept, like the PoN tag); recommended settings `--max-breakpoint-std 100 --min-breakpoint-reads 5 --min-breakpoint-distance 10000` (the original `10` cutoff proved too tight — a real high-depth fusion's junction spreads over tens of bp from splice isoforms + transition-point noise, while artifacts scatter over thousands-to-millions of bp, so `100` separates them with orders-of-magnitude margin). `detect_fusions` now logs `releasing in-memory index... → fusion detection complete` so the post-write teardown pause is attributable. Experimental-only; no schema change (new `filter` values in an existing column). WDL `geac_fusions.wdl` exposes all three inputs.
- **Released:** v0.4.50 — Interval-scatter for `geac collect`. Split one sample's collection across genomic shards and gather a result **identical** to an unsharded run, so whole-genome duplex samples that took >24h in a single pass parallelize across tasks. New `geac split-intervals` (balanced, disjoint BED shards from a BED/Picard interval list) and `geac aggregate-metrics` (exact per-sample `sample_metrics` — means *and* medians — reconstructed from per-shard depth histograms emitted by `collect --sample-metrics-partial`). `collect --region <BED>` now clips emitted loci to each interval; htslib previously over-emitted boundary columns, which would double-count across shards. `geac_cohort.wdl` gains `scatter_interval_list` / `scatter_count`: when set, each sample scatters across shards (a shared `SplitIntervals` + nested sample×shard `Collect` + per-sample `AggregateMetrics`) then merges via the unchanged `Merge`; unset preserves the original one-collect-per-sample behavior. `n_target_positions` / `n_target_positions_covered` widened `i32 → i64` (a genome-wide target exceeds `i32::MAX`). No new columns; `geac merge` unchanged (disjoint shard loci concatenate).
- **Released:** v0.4.49 — gnomAD index recorded for IGV. New `--gnomad-index` / `--gnomad-index-uri` flags on `collect` populate a new `gnomad_index_path` column (URI wins), aggregated into the `samples` table; the Explorer's gnomAD-track-index defaults to it, so IGV references the exact index instead of inferring `.tbi`. Exposed as `gnomad_index_uri` in collect/cohort WDLs. Additive nullable column (`DUCKDB_SCHEMA_VERSION` unchanged; old inputs merge with NULL). Known limitation: these flags record the index for IGV but do **not** change geac's own AF annotation, which still needs the gnomAD index co-located with `--gnomad` — rust-htslib's VCF reader has no explicit-index entry point.
- **Released:** v0.4.48 — Explicitly-specifiable BAM/CRAM index. New `--index <PATH>` flag on `collect`, `coverage`, and `fragments` opens the input against an index that lives under a different name or directory than the BAM (via htslib `from_path_and_index`), for sites where BAM and `.bai`/`.crai` are not stored together. The explicit index path is recorded as `bai_path` (unless `--bai-uri` is given, which wins), so IGV sessions reference exactly that index. All cohort/collect/coverage/fragments WDLs now pass `--index` from their localized index inputs. Also: cohort-wide `family_size_tags_all` scalar in `geac_cohort.wdl` (avoids repeating a per-sample array); Explorer region/gene filtering is now case-insensitive. No schema change (`bai_path` already present).
- **Released:** v0.4.47 — Flexible `--pipeline` and configurable family-size tags. `--pipeline` is now a free-text label stored verbatim in the `pipeline` column (was a closed `fgbio`/`dragen`/`raw` enum). Which aux tags encode family size is decoupled into a resolvable `FamilySizeScheme`: `fgbio` and `dragen` remain built-in presets with their exact prior logic (`aD`/`bD`/`cD` with `cD`→`aD+bD` fallback; `XW>0 else XV`), and a new `--family-size-tags ab=XX,ba=YY,total=ZZ[,fallback=sum|none]` flag lets any other pipeline declare its own tags (absent tags yield null family size). Exposed in `geac_collect.wdl` (single value) and `geac_cohort.wdl` (per-sample array). No schema change. Note: unknown `--pipeline` values no longer error — they record the label and read no family size unless `--family-size-tags` is given.
- **Released:** v0.4.46 — Merge robustness and pipeline plumbing. `geac merge` now validates the DuckDB `schema_version` of every attached cohort input before copying: a mismatch against the current `duckdb-v4` schema hard-fails with an actionable message instead of silently dropping/NULL-filling columns through `INSERT ... BY NAME`; legacy inputs that predate version stamping (no `geac_metadata`) log a warning rather than failing. New `FL` per-read layout tag on the fusion evidence BAM, emitted through a shared renderer (`src/fusions.rs`, `src/kmer.rs`, experimental `diagnose-fusion`). `--exclude-tag TAG:VALUE` is now exposed cohort-wide in `geac_cohort.wdl` (was `geac_collect.wdl`-only). No schema change.
- **Released:** v0.4.45 — Fusion false-positive diagnostics and a tag-based read filter. Two experimental commands attribute a suspect `GENEA::GENEB` call to its cause: `shared-kmers` (index/reference level — pairs two genes' k-mers, with `--edit-distance N` fuzzy matching for diverged paralogs, `--check-reference` genome-wide copy counts, and `--index` to flag which matched k-mers are real index k-mers); and `diagnose-fusion` (read level — from a `fusions --reads-output` evidence BAM, reports a homology-vs-junction coherence verdict, the reads' original alignment, a suspicious-k-mer table flagging 1-substitution error paths, and a per-read A/B layout track). `geac collect --exclude-tag TAG:VALUE` drops reads by exact aux-tag value (repeatable). `fusions` BAM/CRAM scan now logs percent-complete and ETA. Experimental-only; no schema change. (`VERSION`/`GEAC_VERSION` also realigned to Cargo from a missed 0.4.44 bump.)
- **Released:** v0.4.44 — Parallel genome scan for `--edit-distance-filter` and `--check-genome-uniqueness`: rayon parallelism over chromosomes; `--threads N` flag (0 = all CPUs, default); eliminates the O(138×N) `neighbor_to_candidates` pre-build that OOM'd on 64 GB for 400-gene panels. WDL `cpu` now wired to `threads`.
- **Released:** v0.4.43 — Fix genePredExt+bin chromosome column: `fields[1]` (transcript accession) was used instead of `fields[2]` (chromosome), causing `ncbiRefSeq.txt.gz` to produce a silent empty index.
- **Released:** v0.4.42 — `build-fusion-index --gene-annotation`: renamed from `--gtf`; now accepts GTF (`.gtf`, `.gtf.gz`) and GenePred/refFlat (`.txt`, `.txt.gz`, e.g. `ncbiRefSeq.txt.gz`) formats with auto-detection. Empty-annotation guard added. ANSI escape codes suppressed when stderr is not a terminal.
- **Released:** v0.4.41 — `build-fusion-index --edit-distance-filter N`: discards candidate k-mers with any reference genome k-mer within Hamming distance N; use N=1 to ensure no single-base sequencing error in a reference read can produce the candidate k-mer. Triggers a full genome scan independently of `--check-genome-uniqueness`. WDL updated.
- **Released:** v0.4.40 — `geac cohort inspect`: validates a merged DuckDB against the schema manifest (table presence, row counts, column drift); `coverage_intervals` and `fusions` added to `schema/geac_schema.json` contract; CI test-running workflow (`cargo test` + `pytest app/tests/` on every push/PR); `geac_collect.wdl` resource-doc drift fixed; AI plot builder tab removed from Explorer; README split into focused reference docs under `docs/`.
- **Released:** v0.4.39 — Code audit log added to `docs/CODE_AUDIT.md`; no Rust or pipeline changes.
- **Released:** v0.4.38 — `--bai-uri` flag on `geac collect`; `bai_path` column in Parquet output and DuckDB `samples` table; `geac_cohort.wdl` now passes `bam_uri`/`bai_uri` (was missing); Explorer `sample_resources()` reads `bai_path` from DuckDB for automatic IGV index wiring.
- **Released:** v0.4.37 — `compute-uniqueness-map` experimental command: for every genomic locus compute the smallest k for which the k-mer is genome-unique; bedgraph output; `--regions` for panel-targeted output. `build-fusion-index --min-gene-kmers` default changed 100 → 1 (keep any gene with at least one usable k-mer). `geac merge --on-target-tsv`: optional TSV of on-target alt-base calls mirroring the explorer main summary table columns, silently skipped when no `on_target` column. `geac_cohort.wdl` now outputs `cohort_manifest` (TSV of original BAM/BAI URIs and per-sample metadata) and `cohort_on_target_tsv` (when `export_on_target_tsv=true`). `geac_fusions.wdl` wires `--skip-version-check`.
- **Released:** v0.4.36 — Fusion k-mer blacklist: new `geac experimental build-fusion-kmer-blacklist` command aggregates per-sample `--kmer-hits-output` TSVs from normal samples into a k-mer-level PoN Parquet (`kmer_hash`, `n_pon_samples`); `fusions` gains `--fusion-kmer-blacklist` and `--min-kmer-blacklist-samples` — a read must have `--min-kmer-hits` *non-blacklisted* k-mer matches to contribute to evidence (blacklisted k-mers still help once a read passes on clean evidence, complementing the gene-pair `--fusion-pon`). Version recording added to fusion index (`meta` table) and PoN DuckDB (`geac_metadata`); `--skip-version-check` downgrades mismatch to a warning. Progress logging added to the detail BAM pass. WDL and `EXPERIMENTAL.md` updated.
- **Released:** v0.4.35 — Fusion PoN filter tagging + robustness: `--max-pon-samples` now *tags* PoN-recurrent fusions with a new `filter` column (`PASS`/`pon`) instead of dropping them; `geac merge` fails fast with an actionable message when a mis-named (non-`.fusions.parquet`) fusion Parquet is routed to the locus table; fusion-index load reserves capacity and applies `--max-kmer-copies` at load time (lower peak RSS, dropping the redundant copies map); a recorded `kmer_size` in the index is validated against `--kmer-size`; breakpoint chromosome fallback + determinism fixes; new unit + integration test coverage for the fusion caller.
- **Released:** v0.4.34 — Fusion caller quality overhaul: junction-coherence filter (`--min-coherent-fragments`, `--min-anchor-kmers`); `n_spanning_reads` and `n_coherent_fragments` output columns; seven correctness fixes to `fragment_top_pair`, `assign_gene`, and the secondary-output pipeline (see `docs/DEVELOPMENT_LOG.md`). WDL updated.
- **Released:** v0.4.33 — `geac experimental fusions --breakpoints-output`: per-fusion breakpoint coordinates derived from junction-spanning reads (median position, contributing-read counts, spread), computed in the same second BAM pass as `--kmer-hits-output`. Helper scripts committed: `reconstruct_fusions.sh` (de novo junction reconstruction, experimental) and `make_manifest.py`. Docs refreshed across `EXPERIMENTAL.md`, README WDL table, and `DEVELOPMENT_LOG.md`.
- **Released:** v0.4.32 — `kmer_pos_in_read` column added to `--kmer-hits-output` TSV (0-based k-mer offset within read sequence, enabling fusion breakpoint localization from spanning reads); `reads_bam_index` (.bai) added as a named WDL output in `geac_fusions.wdl`.
- **Released:** v0.4.31 — Fusion WDL workflows (`wdl/experimental/`) and `fusions --kmer-hits-output` memory fix: k-mer hit detail now collected in a targeted second BAM pass over fusion-supporting reads only, eliminating gigabytes of per-read accumulation on deep BAMs.
- **Released:** v0.4.30 — Fusion-index k-mer copy-number quantification and two-tier (panel vs genome) uniqueness. `build-fusion-index` gains `--max-genome-copies` (retain near-unique k-mers), `--gene-stats-output` (per-gene uniqueness + copy buckets), `--copy-histogram-output`, and `--bed-output-by-copies` (per-tier BEDs with a full-GTF gene-annotation column on tiers ≥2); the index now stores per-k-mer `genome_copies`. `fusions` gains `--max-kmer-copies` (re-tighten/relax uniqueness at call time) and tags `--reads-output` records with `FX:Z:GENEA::GENEB`. Experimental commands documented in [docs/EXPERIMENTAL.md](docs/EXPERIMENTAL.md).
- **Released:** v0.4.29 — Experimental command isolation: fusion / k-mer subcommands (`build-fusion-index`, `fusions`, `extract-gene`, `locate-kmer`) moved under `geac experimental <...>` to make their pre-production status explicit. Stable command surface unchanged. KmerIter position fix; BED output of unique k-mer intervals; `extract-gene` gains `--complement-output`, `--kmer-hits-output`, and redacted `--debug-region` diagnostics; `locate-kmer` gains `--gene-annotations`; `fusions` includes secondary/supplementary/unmapped reads (k-mer matching is alignment-independent) with `--min-mapq` defaulting to 0.
- **Branch policy:** all work goes directly to `main`.
- **Releases are gated on Rust/pipeline changes**, not Explorer UI changes. UI improvements
  ship in whatever version is current.
